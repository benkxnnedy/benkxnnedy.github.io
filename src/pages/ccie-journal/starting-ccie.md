## What changes now

The focus moves from knowing technologies well enough to pass a written exam toward being able to configure, verify and troubleshoot them quickly under pressure.

That means spending less time asking *what command configures this?* and more time asking:

- What state should the control plane be in?
- What evidence proves that?
- How would this fail?
- Which command or packet capture narrows the fault fastest?
- What changes when several technologies interact?

## The lab rule

Every major topic should eventually include a working state, at least one failure state, verification commands, and a short explanation of the underlying behaviour.
